# Tsareich2 前史アーカイブ (Prehistory)

このディレクトリは、Tsareich2 の **架空戦記としての前史（ゲーム開始 1936.1.1 に至るまでの歴史）** を、
**人間にもAIエージェントにも読みやすい形** で蓄積するための場所です。

ゲーム本体（HOI4）はこのディレクトリを読み込みません。ここは **設定資料・参照専用** です。
実装（focus / event / idea / decision など）を行うAIや作業者が、世界観と矛盾しないように参照します。

> 技術的なスクリプト・リファレンスは `documents/` にあります。前史（物語・世界観）とは役割が異なるため統合しません。
> 開発の設計メモ・計画は `docs/plan/` にあります。

## 1. このアーカイブの読み方（AI向け）

実装作業の前に、最低限これだけ読めば文脈が掴めます。

1. この `README.md`（書式と世界観の起点）
2. `TIMELINE.md`（POD→1936 の背骨年表）
3. `ENTITIES.md`（国家・人物・派閥の名称 ↔ ゲームID 対応表）
4. 対象に関係する `nations/<TAG>.md` および該当 `events/*.md`

実装したら、根拠となった前史ファイルの `implements:` を更新して同期させること。

## 2. ディレクトリ構成

```text
docs/prehistory/
  README.md      # この書式定義・世界観の起点（最初に読む）
  INDEX.md       # 全ファイル索引（1行1ファイル）
  TIMELINE.md    # POD→1936 の背骨年表。各項目 → events/*.md へリンク
  ENTITIES.md    # 国家/人物/派閥のレジストリ。lore名 ↔ ゲームID
  _templates/    # 新規ファイルの雛形（コピーして使う）
    event.md
    nation.md
    faction.md
  events/        # 大事件を1つ1ファイル（YYYY_slug.md）
  nations/       # 国別前史（TAG.md）
  factions/      # 同盟・条約機構・ブロック
```

二つの軸でアクセスできるようにします。

- **時系列軸:** `TIMELINE.md` → `events/`
- **主体軸:** `ENTITIES.md` → `nations/` / `factions/`

同じ事件を二重に書かないこと。一方を本文（正典）、他方はリンクにします。

## 3. ファイル書式（全ファイル共通）

すべてのファイルは **YAMLフロントマター + Markdown本文** にします。
フロントマターにより、AIは「ROMが関与する1936年以前の出来事」のような抽出を機械的に行えます。

### フロントマター仕様

| フィールド | 必須 | 値 | 説明 |
|---|---|---|---|
| `id` | ✅ | 文字列 | 安定したID。events はファイル名と一致、nations は TAG。本文リンクの参照先。 |
| `title` | ✅ | 文字列 | 日本語タイトル。 |
| `type` | ✅ | `event` / `nation` / `faction` / `character` | ファイル種別。 |
| `date_start` | ◯ | `YYYY.M.D` | HOI4日付形式。事件の開始、国家なら建国/POD。 |
| `date_end` | – | `YYYY.M.D` | 継続事象の終端。単発なら省略。 |
| `tags` | ◯ | `[GER, RUS]` | 関与する実装TAG（大文字3字、ゲームと一致）。 |
| `canon` | ✅ | `canon` / `draft` / `proposed` | 設定の確定度。下記参照。 |
| `implements` | – | リスト | この前史が根拠づける実装オブジェクト（focus/idea/event/decision/state）。 |
| `related` | – | リスト | 関連する他ファイルの `id`。 |
| `sources` | – | リスト | 史実の参照や設計メモ（任意）。 |

### `canon` の意味（重要）

- `canon` … 確定設定。実装の根拠にしてよい。
- `draft` … 執筆中。大筋は決まっているが細部は変わりうる。
- `proposed` … 検討中の案。**まだ既成事実として実装してはいけない。**

これにより「未確定の前史を勝手に実装する」事故を防ぎます。

### 本文構成

種別ごとに `_templates/` の雛形に従ってください。共通して先頭に **「概要」（2〜3文）** を置き、
AIが要約だけで把握できるようにします。末尾には必ず **「ゲームへの反映」** を置き、
前史と実装オブジェクトの対応を明示します。

## 4. 命名規則

- イベント: `events/YYYY_kebab-slug.md`（先頭が年なので自然に時系列ソートされる）
- 国家: `nations/TAG.md`（大文字3字、ゲームのTAGと一致）
- 派閥: `factions/kebab-slug.md`
- 相互参照は **フロントマターの `id`** を正とし、本文では相対リンクで結ぶ。
  例: `[ブレスト体制](events/1918_brest-litovsk-permanence.md)`

---

## 5. 新規ファイルの作り方

1. `_templates/` の該当雛形をコピーする。
2. フロントマターを埋める（特に `id` / `canon` / `tags`）。
3. 本文を書く。
4. `INDEX.md` に1行追加する。
5. 時系列に関わるなら `TIMELINE.md` に行を追加する。
6. 関係する国家/派閥が `ENTITIES.md` に無ければ追加する。

---

## 6. 整形ルール（読みやすさ）

- 1ファイル1トピック。肥大化したら分割する。
- 見出しは `##` から開始（`#` はタイトル相当として1ファイル1つ）。
- 固有名詞の初出にはできれば対応TAGを併記する。例：「セルビア王国（SER）」。
- 年は HOI4 形式 `YYYY.M.D` を基本とする（本文の散文では和暦混在可）。
- 確定していない箇所は `<!-- TODO: ... -->` で明示的に残す。
